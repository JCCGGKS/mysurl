# Base*系列编码

| 编码 | 字符数量 | 特点 | 用途 |
| --- | --- | --- | --- |
| Base16 | 16 | `0-9 A-F` | 哈希、MD5、SHA |
| Base32 | 32 | 不区分大小写 | 文件名、密钥 |
| Base58 | 58 | 无易混淆字符 | 比特币、钱包 |
| Base62 | 62 | 纯字母数字 | 短链、邀请码 |
| Base64 | 64 | 含 `+ / =` | 图片、二进制 |
| Base64URL | 64 | 安全 URL 版 | JWT、Token |

## 各方案说明

### Base16

- 字符集：`0-9 A-F`
- 本质：十六进制表示
- 优点：通用、直观、实现简单
- 缺点：编码后长度偏长
- 常见场景：哈希值展示，如 MD5、SHA

### Base32

- 字符集数量：32
- 特点：通常不区分大小写
- 优点：比 Base16 更短，适合人工抄写和文件名场景
- 缺点：长度仍然偏长
- 常见场景：密钥、文件标识、OTP 相关编码

### Base58

- 字符集数量：58
- 特点：去除了易混淆字符，如 `0 O I l`
- 优点：更适合人眼识别和人工输入
- 缺点：通用性不如 Base64/Base62
- 常见场景：比特币地址、钱包地址、邀请码

### Base62

- 字符集数量：62
- 特点：只包含数字和大小写字母
- 优点：短、可读、适合 URL 路径
- 缺点：不同实现的字符顺序可能不同，需在项目内固定规则
- 常见场景：短链、邀请码、短 token
- Base62 无官方强制标准，但字符顺序本身就是编码规则

### Base64

- 字符集数量：64
- 特点：包含 `+`、`/`，末尾可能出现 `=`
- 优点：编码效率高，生态成熟
- 缺点：不适合直接作为 URL 路径片段
- 常见场景：图片、文件、二进制内容传输

### Base64URL

- 字符集数量：64
- 特点：Base64 的 URL 安全变种，通常使用 `-`、`_`
- 优点：适合 URL、Cookie、JWT
- 缺点：可读性和短链美观度通常不如 Base58/Base62
- 常见场景：JWT、Token、签名串

## 短链场景建议

- `Base16` 和 `Base32` 长度偏长，不适合作为短链码
- `Base64` 和 `Base64URL` 更适合编码二进制数据，不是短链首选
- `Base58` 和 `Base62` 更适合短链系统
- 当前项目优先推荐 `Base62`

原因：

- 字符集简单
- URL 友好
- 可读性较好
- 实现成本低
